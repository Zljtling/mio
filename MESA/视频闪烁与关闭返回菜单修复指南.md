# 视频闪烁与关闭返回菜单修复指南

针对你已经接入的 `main.cpp`（2026-10-04，修改前 1704 行左右）。**本次没有直接修改 main.cpp 或项目配置，下面由你手动接入。** 先复制一份 main.cpp 作为备份。行号是修改前的定位参考，修改后会顺延，请同时按函数名与原代码定位。

本次两项改动：视频播放期间保持 EasyX 批量绘制并排除视频子窗口区域；播放中点击游戏窗口右上角 ×，停止视频并回主菜单，游戏进程继续运行。自然播放完也回主菜单，菜单里的「退出游戏」继续关闭进程。

## 问题原因与修正

你接入的代码与上一份指南一致，属于原方案遗漏。

- 原第 1552 行在打开视频前调用 `EndBatchDraw()`。它结束批量绘制，并不是暂停绘制，播放期间因此没有继续保持批量模式。修复后只在游戏真正退出时调用 EndBatchDraw。
- 父窗口没有 `WS_CLIPCHILDREN`，窗口绘图可能覆盖视频子窗口的区域。结合你报告的闪烁，这是当前最主要的刷新冲突嫌疑；修复中补上该样式。实际视觉效果需你接入后检查。
- 右上角 × 首先触发窗口关闭处理。原代码没有拦截 `WM_CLOSE`，EasyX 可以直接销毁窗口或结束进程，主循环未必有机会返回菜单。修复后窗口消息处理只发出一个「关闭视频」请求，由主循环执行视频关闭与菜单重绘。
- 窗口消息可能在 EasyX 的窗口线程处理，而主循环在另一个线程。使用 `std::atomic` 传递请求，避免窗口回调直接操作游戏对象或绘图。

视频文件不用再转换，`EndingVideo` 类、ResetRound、ReturnToMenu、战斗机制与素材加载代码都继续使用。

## 2. 添加窗口显示与关闭处理

找到顶部原第 49 行：

```cpp
Scene scene = Scene::Menu;
```

在它**下面**插入整段代码。必须放在所有类和函数的外面，不要插入 Scene 枚举花括号里：

```cpp
// EasyX 窗口消息与 main 可能在不同线程，用原子变量传递关闭请求
std::atomic<bool> video_is_playing{ false };
std::atomic<bool> video_close_requested{ false };
std::atomic<WNDPROC> original_game_proc{ nullptr };

LRESULT CALLBACK GameVideoWindowProc(HWND hwnd, UINT message,
	WPARAM wparam, LPARAM lparam)
{
	if (message == WM_CLOSE && video_is_playing.load())
	{
		// 播放中点击右上角 ×：只请求返回菜单，不销毁游戏窗口
		video_close_requested.store(true);
		return 0;
	}

	// 其余消息继续交给 EasyX；这里不调用任何绘图或游戏状态函数
	WNDPROC original = original_game_proc.load();
	if (original)
		return CallWindowProcW(original, hwnd, message, wparam, lparam);
	return DefWindowProcW(hwnd, message, wparam, lparam);
}

void RestoreGameWindowProc(HWND hwnd)
{
	WNDPROC original = original_game_proc.load();
	if (original && IsWindow(hwnd))
		SetWindowLongPtrW(hwnd, GWLP_WNDPROC,
			reinterpret_cast<LONG_PTR>(original));
}

bool InstallVideoWindowSupport(HWND hwnd)
{
	// 父窗口绘图时排除视频子窗口区域，避免相互覆盖造成闪烁
	LONG_PTR style = GetWindowLongPtrW(hwnd, GWL_STYLE);
	SetLastError(0);
	if (SetWindowLongPtrW(hwnd, GWL_STYLE, style | WS_CLIPCHILDREN) == 0 &&
		GetLastError() != 0)
		return false;

	WNDPROC original = reinterpret_cast<WNDPROC>(
		GetWindowLongPtrW(hwnd, GWLP_WNDPROC));
	if (!original)
		return false;
	original_game_proc.store(original);
	SetLastError(0);
	if (SetWindowLongPtrW(hwnd, GWLP_WNDPROC,
		reinterpret_cast<LONG_PTR>(GameVideoWindowProc)) == 0 &&
		GetLastError() != 0)
		return false;

	// 应用新的窗口样式，不移动、不改变尺寸，也不抢焦点
	if (!SetWindowPos(hwnd, nullptr, 0, 0, 0, 0,
		SWP_NOMOVE | SWP_NOSIZE | SWP_NOZORDER |
		SWP_NOACTIVATE | SWP_FRAMECHANGED))
	{
		RestoreGameWindowProc(hwnd);
		return false;
	}
	return true;
}
```

这里仅在「播放视频」时拦截 ×。其他消息继续交给原 EasyX 窗口处理；菜单中的退出按钮没有改动。

## 5. 替换播放期间的整段分支

找到 `while (running)` 刚进入后、原第 1492 行的：

```cpp
		if (scene == Scene::Video)
```

把这个 if **完整替换**，原范围大约第 1492～1519 行，包含它自己的左右花括号和最后的 Sleep / continue。**不要替换后面原第 1582 行仅含 continue 的另一个同名条件。**

新分支如下：

```cpp
		if (scene == Scene::Video)
		{
			MSG native_msg = {};
			while (PeekMessageW(&native_msg, nullptr, 0, 0, PM_REMOVE))
			{
				if (native_msg.message == WM_QUIT)
				{
					running = false; // 真正的线程退出消息仍正常处理
					break;
				}
				TranslateMessage(&native_msg);
				DispatchMessageW(&native_msg);
			}
			while (peekmessage(&msg)) {} // 视频中的输入不传给游戏或菜单

			bool close_requested = video_close_requested.exchange(false);
			if (running && (close_requested || ending_video.IsFinished(GetHWnd())))
			{
				// 点击 × 和自然播放完毕共用这一条返回菜单流程
				ending_video.Close();
				video_is_playing.store(false);
				video_close_requested.store(false);
				ReturnToMenu();
				flushmessage();
				last_time = GetTickCount();

				// 视频子窗口移除后立即画菜单，避免停留在黑屏
				cleardevice();
				putimage(0, 0, &img_menu);
				btn_start_game.Draw();
				btn_quit_game.Draw();
				FlushBatchDraw();
			}
			Sleep(10);
			continue;
		}
```

这段不再调用 BeginBatchDraw。点击 × 和自然结束都先关闭视频，再返回菜单并立即重绘；不会把 running 设为 false。真正的 WM_QUIT 仍然处理为退出，不能简单地忽略所有线程退出消息。

注意其中的 `cleardevice` / `FlushBatchDraw` 只在视频已经关闭、scene 已切换到 Menu **以后**执行，不会在正在播放时每帧覆盖视频。
